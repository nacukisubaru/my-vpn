# Настройка клиента, чтобы не ловить блок

## Почему «у тебя в контейнере работает, а у меня блок»

Это главное, что надо понять: **контейнер и телефон создают совершенно разный трафик.**

| | Мой тест в контейнере | Ваш телефон |
|---|---|---|
| Приложений через туннель | одно (`curl`) | **все сразу** (браузер, YouTube, Instagram, Telegram, фоновая синхронизация) |
| Протоколы | только TCP | TCP **+ QUIC/UDP** (YouTube, Instagram, Google любят QUIC) |
| DNS | через туннель | часто **напрямую провайдеру** (утечка) |
| Объём за неделю | ~50 МБ тестами | **18 ГБ** на профиле `main` |
| Время жизни сессии | секунды | часы, постоянные переподключения |
| Исходящая сеть | Mac по Wi-Fi/кабелю | мобильный оператор со своим DPI |

Вывод: контейнер проверяет только **работоспособность** сервера. Он не воспроизводит
профиль трафика, по которому вас и вычисляют.

## Что именно вас выдаёт (по важности)

1. **QUIC/UDP внутри туннеля.** Reality + Vision отлично прячут TCP. Но когда телефон гонит
   UDP-поток (QUIC) внутри VLESS-over-TCP, получается UDP-в-TCP — аномалия, которую DPI видит
   без расшифровки. Это признак №1.
2. **Весь трафик через VPN.** 18 ГБ «иностранного» трафика с одного IP — сам по себе паттерн.
   Особенно когда параллельно открыты яндекс.карты, госуслуги, банк — им VPN не нужен.
3. **Утечка DNS.** Если резолв идёт к провайдеру, ТСПУ видит запросы `youtube.com` от вас
   одновременно с «непонятным» TLS-потоком. Корреляция очевидна.
4. **Mux включён.** Vision не нуждается в мультиплексировании, а mux создаёт характерный рисунок.
5. **Один UUID на все устройства.** ПК и телефон одновременно — одна «личность» с двух сетей.

## Решение: 3 шага

### Шаг 1. Взять «закалённый» конфиг с маршрутизацией

В проекте уже собран [`client/config-hardened.json`](../client/config-hardened.json):

- **блокирует QUIC** (UDP/443) для проксируемых доменов → приложения сами переходят на TCP,
  который защищён Vision;
- **DNS проксируемых доменов идёт через туннель** (DoH 1.1.1.1 внутри VPN) — утечки нет;
- **сплит-туннель**: через VPN только 89 доменов из [`data/rules-proxy.txt`](../data/rules-proxy.txt),
  всё российское и локальное — напрямую ([`data/rules-direct.txt`](../data/rules-direct.txt));
- всё остальное — напрямую (не гоняем весь трафик через сервер).

Пересобирается автоматически при каждой ротации (`sync-client.sh`), так что не устаревает.

### Шаг 2. Выбрать клиент, который это умеет

| Клиент | Платформа | TUN | Сплит по приложениям | Свой routing | Комментарий |
|---|---|---|---|---|---|
| **Hiddify** | Android/iOS/Win/macOS | ✅ | ✅ | ✅ (профили + правила) | **Рекомендую.** Лучшая комбинация TUN + per-app + импорт JSON-конфига |
| **v2raytun** | Android/iOS | ✅ | ⚠️ ограниченно | ⚠️ через подписку | Работает, но маршрутизацию настраивать неудобно — только через JSON-конфиг |
| **NekoBox** | Android | ✅ | ✅ | ✅ (гибко) | Максимум контроля, но интерфейс сложный |
| **Streisand** | iOS | ✅ | ❌ | ✅ | Бесплатный, хороший для iOS |
| **Shadowrocket** | iOS | ✅ | ✅ | ✅ | Платный, самый полный на iOS |

**v2raytun сам по себе не плохой** — это обёртка над Xray, ядро то же. Проблема не в нём,
а в том, что в режиме «весь трафик в VPN» он гонит QUIC и всё подряд. Если остаться на
v2raytun — просто импортируйте `config-hardened.json` (см. ниже), этого достаточно.

### Шаг 3. Не гнать всё

Два уровня:

**A. Сплит-туннель по приложениям** (в Hiddify: `Настройки → Per-app proxy`; в NekoBox:
`Настройки → Split tunneling`):

- **через VPN:** браузер, YouTube, Instagram, Discord, Telegram, GitHub, ChatGPT
- **напрямую:** банки, госуслуги, Яндекс, Карты, такси, доставка, локальные приложения

Это уменьшает объём в разы и убирает «странность» вроде VPN-трафика к Сберу.

**B. Сплит по доменам** — уже сделано в `config-hardened.json`.

## Как импортировать `config-hardened.json` в v2raytun

1. Открыть файл [`client/config-hardened.json`](../client/config-hardened.json), скопировать всё содержимое.
2. v2raytun → `+` → **«Импорт из буфера обмена»** (или «Добавить конфиг → JSON»).
3. Выбрать профиль → подключиться.
4. Проверить: `https://www.cloudflare.com/cdn-cgi/trace` должен показать IP `82.148.226.31`
   (или IPv6 `2a12:5940:b6e2::2`), а `https://2ip.ru` — ваш реальный IP. Так и должно быть.

> В JSON-конфиге зашит текущий ключ. После `./rotate.sh` конфиг пересобирается —
> скопируйте файл заново или обновите подписку.

## Если хотите остаться на простой ссылке `vless://`

Тогда минимум сделайте в v2raytun руками:

| Настройка | Значение | Зачем |
|---|---|---|
| Mux / мультиплексирование | **выключить** | Vision не нужен mux, он даёт лишний рисунок |
| Режим | **TUN / VPN** (не «прокси») | иначе часть приложений обходит туннель и палит вас |
| DNS | **Remote / через прокси** = `https://1.1.1.1/dns-query` | убирает утечку DNS |
| Fragment | опционально: `tlshello`, `1-3`, интервал `10-20` | если режут по сигнатуре ClientHello |
| Сплит-туннель | российские приложения — напрямую | меньше объёма и подозрительности |

## Что НЕ надо делать

- ❌ Гнать через VPN банки/госуслуги — бессмысленно и подозрительно.
- ❌ Держать один профиль на 5 устройствах.
- ❌ Включать VPN «на всякий случай» 24/7 при просмотре локального контента.
- ❌ Использовать один и тот же SNI месяцами (см. [`ROTATION.md`](ROTATION.md)).

## Порядок действий, когда «опять заблокировали»

```bash
./diag.sh                 # что именно сломалось: порт / SNI / ключи / клиент
./rotate.sh               # новый SNI + новые ключи (30 секунд)
```

Затем в клиенте: обновить подписку или переимпортировать `client/config-hardened.json`.

Если `diag.sh` показывает «всё ок», а на телефоне не работает — проблема в клиенте:
смените режим на TUN, отключите Mux, проверьте DNS. Список — в
[CLIENTS.md](CLIENTS.md#подключается-но-работает-только-googlecom-или-часть-сайтов).

## Про объём трафика

На сервере видно: `main` — 18 ГБ вниз, `phone` — 3.6 ГБ. После включения сплит-туннеля
и блокировки QUIC объём через VPN падает в разы (локальный трафик перестаёт идти через UK).
Это и скорость, и скрытность.
