# Ротация: SNI, порты, ключи

Скрипт `./rotate.sh` меняет «отпечаток» сервера, чтобы обойти блокировку/детект DPI.
Каждая ротация сохраняет снапшот с точным временем в `docs/snapshots/`.

## Что можно менять

| Параметр | Что это | Зачем менять |
|---|---|---|
| **SNI / dest** | домен, под который маскируется TLS (Reality проксирует его настоящий сертификат) | если DPI начал резать конкретный домен |
| **Порт** | порт основного входа | если режут по порту/сервису |
| **Ключи** (privateKey/publicKey/shortId) | криптография Reality | если «сгорел» профиль/сессия, сброс отпечатка |

## Быстрый старт

```bash
./rotate.sh                      # случайный SNI + новые ключи (самый частый вариант)
./rotate.sh --list-sni           # посмотреть пул и статусы
./rotate.sh --verify-sni         # перепроверить все домены реальным тестом
```

В конце ротация печатает:
- ссылку для подключения (и обновляет `client/vless-url.txt`);
- путь к QR-коду (обновляется в `qr/`);
- адрес подписки;
- путь снапшота для отката.

## Все команды и флаги

### Основные

| Команда | Что делает |
|---|---|
| `./rotate.sh` | **случайный SNI** из пула (не использованный за последний час) + **новые ключи**. Порт не меняется |
| `./rotate.sh --without-sni` | новые ключи, SNI остаётся прежним |
| `./rotate.sh --sni <домен>` | вручную задать SNI (проверяется TLS 1.3 + h2) + новые ключи |
| `./rotate.sh --change-port` | случайный свободный порт из пула + случайный SNI + новые ключи |
| `./rotate.sh --port <n>` | вручную задать порт + случайный SNI + новые ключи |
| `./rotate.sh --no-keys` | не менять ключи (только SNI и/или порт) |

### Сервисные

| Команда | Что делает |
|---|---|
| `./rotate.sh --list-sni` | таблица SNI: проверен / когда использован / статус (свободен, карантин N мин, не работает) |
| `./rotate.sh --list-ports` | то же для портов |
| `./rotate.sh --verify-sni` | проверить **все** домены из списка реальным тестом туннеля (медленно, ~20 с на домен) |
| `./rotate.sh --verify-sni <домен>` | проверить один домен |
| `./rotate.sh --reset-used` | сбросить флаги «недавно использован» (у SNI и портов) |
| `./rotate.sh --reset-used sni` | сбросить только SNI |
| `./rotate.sh --reset-used ports` | сбросить только порты |
| `./rotate.sh -h` / `--help` | справка |

### Комбинации

```bash
# сменить всё сразу
./rotate.sh --change-port

# только порт, SNI оставить
./rotate.sh --change-port --without-sni

# только SNI, ключи не трогать (быстро, без переимпорта если у клиента тот же pbk)
./rotate.sh --no-keys

# вручную SNI + вручную порт
./rotate.sh --sni www.python.org --port 2053

# вручную SNI, порт не менять, ключи новые
./rotate.sh --sni cdn.jsdelivr.net

# полный сброс всего, кроме ключей
./rotate.sh --change-port --no-keys
```

## Логика карантина (флаг «уже использован»)

Состояние хранится в `data/rotation-state.json`:

```json
{
  "cooldown_minutes": 60,
  "sni": {
    "cdn.jsdelivr.net": { "last_used": "2026-11-05T11:02:18+03:00", "verified": "...", "ok": true }
  },
  "ports": { "443": { "last_used": "..." } }
}
```

- `last_used` ставится автоматически при каждой ротации.
- **60 минут** (настраивается) вариант считается «в карантине» и случайный выбор его пропускает.
  Это чтобы при частых ротациях не возвращаться на только что сожжённый SNI.
- Домены с `ok: false` (не прошли проверку) не выбираются никогда.
- **Если все варианты в карантине** — при следующей ротации флаги сбрасываются автоматически
  и выбор начинается заново (в stderr печатается `ALL-USED-RESET`).

Изменить карантин:

```bash
python3 - <<'PY'
import json; p="data/rotation-state.json"; d=json.load(open(p)); d["cooldown_minutes"]=30
json.dump(d, open(p,"w"), indent=2)
PY
```

## Пул SNI (34 проверенных домена)

Правится руками: [`data/sni.txt`](../data/sni.txt), один домен в строке.
Актуальный список и статусы: `./rotate.sh --list-sni`.

Все 34 домена проверены **реальным тестом туннеля** (не просто TLS-хендшейком): скрипт
временно ставит SNI на сервер, поднимает клиент в контейнере, шлёт запросы и возвращает
прежний SNI. Отсеяны варианты с несовпадением сертификата (nvidia, dropbox, oracle,
docker, twitch, atlassian, notion/www, udemy/www, coursera/www, bbc), без HTTP/2
(store.steampowered.com) и без TLS 1.3 (registry.npmjs.org).

Текущий пул: cdn.jsdelivr.net, cdnjs.cloudflare.com, coursera.org, dl.google.com,
docker.com, notion.so, npmjs.com, pypi.org, udemy.com, www.adobe.com, www.apple.com,
www.autodesk.com, www.cisco.com, www.cloudflare.com, www.debian.org, www.dell.com,
www.epicgames.com, www.figma.com, www.ibm.com, www.intel.com, www.jetbrains.com,
www.lenovo.com, www.microsoft.com, www.mozilla.org, www.python.org, www.reddit.com,
www.renesas.com, www.salesforce.com, www.shopify.com, www.spotify.com,
www.stackoverflow.com, www.stripe.com, www.wikipedia.org, www.zoom.us.

Требования к домену, чтобы он годился для Reality:
1. TLS 1.3 + HTTP/2;
2. сертификат **точно на этот домен** (не на соседний поддомен — иначе заметно);
3. стабильно доступен с сервера по IPv4 и IPv6;
4. не заблокирован в РФ (иначе ТСПУ может резать по SNI).

После правки списка:

```bash
./rotate.sh --verify-sni          # проверит ВСЕ домены реальным туннелем
./rotate.sh --list-sni            # посмотреть результат
```

Проверка (`verify-sni.sh`) делает не просто TLS-хендшейк, а **полный тест**:
временно ставит SNI на основной вход → поднимает клиент в контейнере → шлёт запросы →
возвращает прежний SNI. Домен попадает в пул только если туннель реально прошёл.

## Пул портов

Файл [`data/ports.txt`](../data/ports.txt). Только «веб-подобные» порты (на них Reality
выглядит как обычный HTTPS). Занятые порты (22/2096/38217 и порты других инбаундов)
скрипт исключает автоматически.

При смене порта скрипт:
1. открывает новый порт в `ufw`;
2. закрывает старый (кроме 443 — его оставляет открытым);
3. обновляет ссылки/QR.

## Что происходит при ротации (по шагам)

1. Снапшот `docs/snapshots/<дата>_<время>-rotate/` (инбаунды, клиентский конфиг, ссылка, ключи).
2. Выбор SNI (вручную / случайно / без изменений).
3. Выбор порта (вручную / случайно / без изменений).
4. Проверка SNI на сервере (TLS 1.3 + h2).
5. Генерация ключей `x25519` + двух shortId.
6. Применение через API панели (xray перезапускается на лету).
7. `sync-client.sh`: пересборка `client/*.json`, `client/vless-*.txt`, `qr/*.png`, `secrets/vpn.json`.
8. Печать итога: ссылка, QR, снапшот.

## Проверки, которые скрипт делает сам

Ротация не считается успешной, пока не выполнено всё:

| Шаг | Что проверяется | Что будет при провале |
|---|---|---|
| 0/8 | панель отвечает валидным JSON (3 попытки) | стоп, rc=1 |
| 2/8 | SNI найден в пуле | стоп, rc=1 |
| 4/8 | домен отдаёт TLS 1.3 + HTTP/2 с сервера | стоп, rc=1 |
| 6/8 | панель вернула `success:true` | стоп, rc=1 |
| 6b/8 | **порт реально слушается** (`ss -tulpn`) | 3 попытки `systemctl restart x-ui`, затем стоп |
| 8/8 | туннель работает в контейнере | предупреждение, rc=2 |

Пункт 6b появился не просто так: при смене порта через API 3x-ui снимает старый
слушатель и **не поднимает новый** — вход остаётся мёртвым, хотя в логах тишина
и панель показывает «всё включено». Лечится только рестартом ядра.

## После ротации обязательно


**Переимпортировать профиль на всех устройствах** — ключи изменились, старые профили
«подключаются», но не работают. Быстрее всего через подписку: клиент подтянет новый конфиг сам.
